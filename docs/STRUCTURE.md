# 화풍공방 구조

사용자 2026-11-10: 「구조화 방안 좀 생각해줘. 확장성을 고려해서」 → 「만드는 의의는 지금 부품구조를 테스트 해보려고 … 이미지 생성은 gpt 세션쪽에 … 세션마다 텍스트 제한이 있어서 이미지 생성은 끊어가며 할거야. 그래서 저장구조와 검색구조에 신경을 써야되는데」 → 「응 그렇게 만들어줘」.

세 가지를 지킨다.
- 세션은 **일감 하나만** 읽고 끝낼 수 있다(칸 4개, 지시문이 다 들어 있다).
- 상태는 **파일이 있는지**로 안다 — 세션끼리 같은 파일을 고치지 않는다(그림 한 장에 기록 하나).
- 색인은 **워크플로가 다시 짓는다** — 사람도 세션도 고치지 않는다.

## 0. 초점 — 지금은 문앙 · 무협

`data/focus.json` 이 지금 시험하는 캐릭터 · 세계를 정한다(사용자 2026-11-10 — 화풍 비교가 먼저라 캐릭터 통일성이 중요하다). `make-job` 기본값 · 화면 기본값 · NEXT.md 첫 줄이 이것을 따른다. 노출도 여기서 — 지금 `slit`(문앙 복사본에만 더한 단계 — 쇄골 · 팔 + 높은 트임으로 한쪽 다리 허벅지까지, 같은 날 「1차때처럼 다리라인 좀 더 보여야겠어」 — 그 앞은 moderate(같은 날 「노출은 너무 low로 했나봐. 피부결 다리나 흉부쪽에 조금 보였으면 해」 — 그 앞은 low)(노출 줄 원래 꼴 `Exposure (low): …`, 칸 이름 끝 `-low`. 사용자 2026-11-10 「bold 를 화풍비교에선 빼자」 → 「skin shown low 로 낮춰줘」 → 「그냥 exposure 로 쓰자」). bold 는 화풍이 정해진 뒤 `--exposure bold` 옵션으로. `none`(노출 줄 없이)도 쓸 수 있다.

초점 밖 일감(`make-job --off-focus` — 사용자가 정할 때만)은 REQUEST.md 첫머리에 「초점 밖 · 사용자가 정한 일감」 이 붙고 NEXT.md 표의 이름 칸에 「초점 밖 · 사용자가 정함」 이 붙는다 — GPT 세션은 NEXT.md 첫 줄(「문앙 무협만」)의 예외로 그 일감을 그린다(11차 넓혀 보기에서 더했다).

## 0.1 축 담당 범위 · 공통 문구 (2026-11-10)

사용자가 가져온 검토안 [docs/AXIS_REVIEW.md](AXIS_REVIEW.md) → 「1. 크고 둥근 눈으로. 2. 삼국지 설계표도 다 수정해줘. 3. 그 순서로 진행해줘」.
- 축 이름 · 담당 범위는 `data/parts.json` axes[].rule — 방향 · 얼굴 표현 · 렌더링·채색 · 조명·색조 · 이펙트. 2D · 3D · CGI · 사진은 렌더링·채색, 실제 나이 · 얼굴 크기 · 생김새는 캐릭터 설계(고정 조건).
- 캐릭터 공통 문구는 복사본의 덮어쓰기(`data/subjects/<id>.overrides.json` — 원본 줄은 `original` 에)로 고친다. 문앙: 머리말 「character card illustration」 → 「character image」, 얼굴 비율 줄의 「in this style」 빼기, 무협 의상의 「a plumed helmet or a war headband」 → 「a war headband with a single white plume」, 판타지 의상의 「a plumed helm or circlet」 → 「a circlet with a single white plume」(머리 장식 고정 — 6차 반복에서 깃털 · 머리 윤곽이 그릴 때마다 달라져 화풍 비교를 흐렸다. `worlds` 로 세계를 집는다). 시간대 · 하늘 말은 두 번 넣었다가 뺐다(7 · 8차 — 하늘이 그림 전체 톤을 바꿔 화풍 차이처럼 보였다. 대조군 애니 붓이 하늘만 바뀌어도 「느낌이 달라져서 애매함」. 사용자 「시간 말은 빼긴 해야하는데」 — 1~6차와 같은 조건, 하늘색은 반복 장수로 거른다). 눈 모순은 삼국지 설계표에서 고쳤다(sam-atelier 89ab31a).
- 부품 v2(같은 날 사용자 v2 표 → 「classical, fantasy_paint는 내리자. 그리고 kr_game_keyart 추가해주고. jp_light_novel … 추가해줘」): 축을 넘던 말 · 부정 말을 정리하고 판마다 한글 이름(versions[].ko). 짝은 `pairs`(추천 — 막지 않음, 화면에 「검증 전 짝」) · `requires`(진짜 모순 — 막음, 지금은 실사 영화 → 사진 · 포토리얼 CGI 렌더링만)로 나눴다. 이펙트 `none` = 미지정(빈 문장), `off` = 없음(avoid 로 억제). 조합 이름은 판과 상관없이 부품 열쇠로 찾는다(`recipeNameOf` — 1차 v1 그림도 제 이름).
- 공통 문구가 바뀌었으니 새 기준은 **2차** — 1차(옛 문구 · 부품 v1) 그림과 견줄 때는 화풍만 다른 게 아니다.

## 1. 이름

| 대상 | 꼴 | 예 |
|---|---|---|
| 부품 | `축/열쇠@판` | `face/semi_soft@v1` |
| 조합 | 축 차례(방향 · 얼굴 · 채색 · 빛 · 이펙트)로 `코드 + 판 번호`, `-` 로 | `km1-ss1-sm1-mu1-xf1` |
| 캐릭터 | `공방.이름` | `sam.wenyang` · `el.fe` |
| 칸 | `<조합>__<캐릭터>__<세계>-<갈래>[-<노출>]` | `km1-ss1-sm1-mu1-xf1__sam.wenyang__samguk-world` |
| 그림 | `<칸>__<모델>__<번호>` | `…__samguk-world__chatgpt__1` |

- 부품 판이 조합 이름에 들어간다 — 부품을 고쳐도 옛 그림과 이름이 겹치지 않는다.
- 노출은 캐릭터 기본값(bold)이 아닐 때만 붙는다(`-moderate` · `-low`).
- 모델: `chatgpt`(GPT 세션) · `api26` · `api25` — 세션 그림과 API 그림을 섞지 않는다(사용자: 세션이 하관을 길게, 눈을 째지게 그리는 경향).
- 번호는 같은 칸을 여러 장 그릴 때(`make-job --repeat`) — 한 장의 운인지 경향인지 보려고.

## 2. 부품 · 조합 · 캐릭터

- `data/parts.json` — 축 다섯, 축마다 부품. 부품 = `code` · `ko` · `current` · `versions[{v, text, avoid?, models?, worlds?}]` · `only?`.
  - 화풍 문단 = 방향 + 얼굴 + 채색(이 차례 — 나라 말이 앞에 올 때 얼굴에 가장 먹혔다). 빛 줄 = `Light: ` + 빛 + 이펙트.
  - `only` — 같이 쓸 수 있는 다른 축 부품. 어긴 조합은 「짝 안 맞음」(지시문을 짓지 않는다).
  - `models.<모델>` · `worlds.<세계>` — 그 모델 · 세계에서만 다른 글(예: 메카 빛).
  - 처음 판은 삼국지 공방 새 화풍 열(2026-11-10)을 축별로 끊은 것 — 원본 문장과 글자가 같지는 않다.
- `data/recipes.json` — 이름 붙인 조합만. 이름 없이도 조합 이름(`km1-…`)으로 어디서나 쓸 수 있다.
- `data/subjects/<id>.json` — 시험 캐릭터 복사본. 세계마다 `head` · `faceFrame` · `character[]` · `costume[]` · `exposure{bold,moderate,low}` · `scene[]` · `constraints[]`, 출처(공방 · 커밋 · 날짜). 화풍 말(Style · Light · Mood)은 빼고 담는다. 목록 `data/subjects/index.json`.
- 지시문(`lib/build.js` build) — 머리말 / `1. STYLE`(화풍 문단 + 얼굴 비율) / `2. CHARACTER` / `3. COSTUME AND EQUIPMENT — 장르`(+ 노출) / `4. SCENE`(구도 앞에 빛 줄) / `5. CONSTRAINTS`(+ 부품의 피할 것).

## 3. 일감 · 수거

```
여기(코드)                       그림 저장소                                 GPT 세션
make-job ──────────────────────▶ jobs/<일감>/REQUEST.md · slots.json · prompts/
                                 jobs/NEXT.md ◀── 수거가 다시 씀
                                                       ◀────────────────── NEXT.md → 일감 하나 → 그림
                                 inbox/<그림 이름>.png ◀──────────────────── 올림(main push)
                                 수거 워크플로(tools/ingest.py)
                                   → img/<캐릭터>/<세계>/<그림>.webp · thumb/… · rec/<그림>.json
                                   → index/images.json · blocked.json · pending.json · problems.json · jobs/NEXT.md
```

- 일감 하나는 **칸 10개까지**(`--size`, 사용자 2026-11-10 「4장보다 한 번에 맡기는 양 더 늘려도 돼」 — 처음엔 4). 아직 아무도 손대지 않은 일감은 `make-job --merge all` 로 차수 · 모델 · 캐릭터별로 크게 다시 묶는다 — 옛 일감은 지우지 않고 `retired` · `merged_into` 만 적는다(NEXT.md · 수거 · 겹침 검사에서 빠진다).
- `make-job` — 칸을 정하는 길 둘: `--recipes a,b` · `--base <조합> --vary <축>[=k1,k2]`. 캐릭터 · 세계 여럿 가능. 이미 그린 칸 · 열린 일감에 있는 칸은 빠진다(`--repeat` 면 번호를 올려 다시, `--times N` 이면 칸마다 N 장을 한 일감에). 칸 4개씩 끊는다(`--size`).
- 일감 이름 `j0001[-label]` — 차례대로. 일감 폴더는 지우지 않는다(기록이 가리킨다).
- **차수**(`round`, `make-job --round N` — 기본은 가장 최근 일감의 차수): 시험 단계 묶음. 화면 검색 조건이 「1차 › 문앙 · 2차 › 문앙 · 1차 › 철」 꼴로 차수 × 캐릭터를 묶는다(사용자 2026-11-10). 색인의 `round` 는 일감에서 다시 읽는다 — 일감의 차수를 고치면 색인도 따라간다.
- 세션이 올리는 것: 그림 — 다른 공방 GPT 세션과 같게 **WebP(품질 90, 1024×1536)로 바꿔 일감 하나 한 커밋**(사용자 2026-11-10 「이미 다른 공방들은 chatGPT 세션에서 이미지 잘만 올리고 있는데」 — PNG 원본을 한 장씩 올리라던 첫 판에서 세션이 업로드 중 Too many requests 로 멈췄다. 받는 쪽은 png · jpg 도 받는다) · `<그림>.blocked.txt`(거절 문구) · `<그림>.note.txt`(메모, 선택).
- API 로 그리는 길(사용자 2026-11-10 「키는 클로드코드의 여러 세션에서 gpt api 도구를 위한 키야. 여기서도 쓰니까」): `make-job --model api26|api25` → `tools/draw-api.cjs <일감>`(같은 지시문으로 한 번 더 → 그래도 막히면 `.blocked.txt`) — 그림 옆 `<그림>.gen.json`(모델 · 사용량 · 시간)은 수거가 기록의 `generation` 으로 옮긴다. NEXT.md 는 GPT 세션에게 chatgpt 일감만 고르라고 한다.
- 수거 — 2:3 이면 1024×1536 으로 맞추고(아니면 그대로 · 기록에 남김) webp 90 · 썸네일(긴 변 512) · 기록. 모르는 이름 · 이미 있는 그림은 inbox 에 두고 `index/problems.json` · NEXT.md 에 적는다(덮지 않는다). 그때 워크플로가 빨갛게 끝난다.
- 끊겨도 된다: 올라간 그림만 끝난 칸. 다음 세션이 같은 일감을 열면 `rec/` 에 없는 칸만 그린다.
- **예약**(사용자 2026-11-10 「job 예약기능도 필요하겠다. 한 세션 끝날쯔음에 다른데서 시켰더니 같은 잡을 가져가네」): 세션은 시작 전에 `jobs/<일감>/CLAIM.md` 를 **새 파일로** 만든다(이름 · 시각 두 줄). 이미 있으면(새로 만들기가 실패하면) 다른 일감으로 — 일감마다 파일 하나라 두 세션이 같은 파일을 만들면 뒤의 것이 실패한다. 이어받을 때(사용자가 콕 집었거나 「예약 만료」)는 그 파일 끝에 두 줄을 더 적는다.
  - 수거 워크플로는 **inbox 에 그림이 올 때만** 돈다 — 예약 커밋 직후 워크플로가 main 을 밀면 세션의 다음 커밋(GitHub 앱)이 계속 거절돼 Too many requests 로 멈췄다(사용자 2026-11-10 「두개다 멈춰있어」). 그래서 NEXT.md 예약 칸은 다음 수거 때(또는 Actions 에서 손으로 돌릴 때) 바뀐다 — 진짜 잠금은 `CLAIM.md` 가 있는가다.
  - 수거가 NEXT.md 에 「예약」 칸을 쓴다: — · 「예약 중 · 이름 · n분 전」(아래로 내린다) · 「예약 만료(n분) — 가져가도 됨」. 시각은 그 파일의 마지막 커밋 시각(세션이 적은 시각은 안 믿는다), 만료는 120분(`CLAIM_TTL_MIN`).
  - 예약 파일은 지우지 않는다(누가 했는지 남는다). REQUEST.md 꼴이 바뀌면 `make-job --rewrite all`(칸 · 지시문은 그대로).

## 4. 검색

- `index/images.json` — `{cols, rows}`, 그림 한 장에 한 줄: id · subject · world · kind · exposure · model · n · recipe · direction · face · paint · light · fx(부품은 `열쇠@판`) · job · added · rating · round. 화면은 열 이름으로 읽는다(열을 더해도 옛 화면이 깨지지 않게 끝에 붙인다). 5천 장을 넘으면 캐릭터별로 쪼갠다.
- `tools/find.cjs` — 조건으로 거르기(`--face semi_soft --world samguk`, 판까지면 `semi_soft@v1`) · 빈 칸(`--gaps --base … --vary …` → 있음 · 막힘 · 일감에 있음 · 비었음 · 짝 안 맞음).
- 화면 `index.html` — 그림 찾기(검색 조건 = 「N차 › 캐릭터」 칩, 그림이 있는 묶음만 · 더 거르기는 접어 둠. 그림을 누르면 상세: 그림 크게 → 아래 조합표(축마다 부품 이름 · 열쇠@판 · 문장) → 그림 정보 → 지시문 전문, ‹ › · ← → 로 넘기고 주소 `#img=<그림>` 으로 바로 열린다) · 축 비교(기준 조합 + 축 → 한 줄, 빈 칸 채우는 명령) · 섞어보기(부품 고르면 지시문 · 조합 이름 · 짝 검사) · 일감(NEXT.md). 그림 저장소는 raw.githubusercontent 에서 읽는다(`?img=` 로 바꿀 수 있다).

## 4.1 평가 (2026-11-10)

사용자 「응 평가 칸 붙여줘」. 그림 상세의 조합표 아래 「평가」 — 항목은 `lib/evals.js`(검토안 7.5): 취향 · 의도 반영 · 캐릭터 유지(1~5), 다른 특징 변화(없음 · 조금 · 큼 — 무엇이 변했는지는 메모), 반복 유지(같은 칸이 여러 장일 때만 보인다), 판정(좋다 — 후보로 · 고칠 것 — 부품 문장 · 축 사이 영향 · 내리기), 메모.

- 저장은 **코드 저장소** `data/evals.json`(그림 이름 → 평가). 그림 저장소에 쓰면 GPT 세션이 그림을 올리는 중에 main 이 밀린다.
- 화면 「GitHub 연결」 에 fine-grained 토큰(저장소 style-atelier 하나, Contents 읽기와 쓰기)을 넣으면 「저장」 이 바로 커밋한다(`[skip ci]`). 토큰은 그 기기 localStorage 에만 — 같은 출처(polos0117.github.io)의 다른 공방 화면도 읽을 수 있는 자리다. 토큰이 없거나 실패하면 그 기기에 두고 「대기분 올리기」 로 나중에 올린다.
